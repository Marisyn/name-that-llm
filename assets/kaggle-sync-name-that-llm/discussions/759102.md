## Next target: 0.700. What would actually get us there?

I would like to turn this into an evidence-led community discussion:

1. **Validation that transfers.** What prompt-disjoint split and response-per-prompt distribution best track the hidden task? How do you stress-test one, two or many responses per prompt without assuming a test-set grouping structure?
2. **Complementary errors.** Which evidence adds genuinely different information to a strong public stack: token likelihood, embeddings or sparse style signals? Per-class recall and error overlap would be especially useful.
3. **OOF calibration and fusion.** Has anyone obtained aligned, leakage-checked out-of-fold predictions for a full strong ensemble? I would prefer selecting temperatures/weights inside inner folds, then measuring them on held-out prompt groups.
4. **External-data hygiene.** Which source, prompt-overlap and near-duplicate checks have helped avoid misleading local improvements?
5. **A practical compute budget.** Which changes improve actual scored performance while keeping offline inference inside the competition's nine-hour limit? Runtime, failure cases and fallback behavior matter too.

The plan is to document each change, test it against a fixed comparator, and share the next verified improvement as public code if the evidence supports it. **0.700 is the target, not an achieved result or a promise.**

If you try the Notebook, please share your scored version, validation protocol, runtime and what worked or failed. Suggestions, corrections and collaborative experiments are welcome.
