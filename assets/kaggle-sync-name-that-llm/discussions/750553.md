As far as I know there is no place to see them. Kaggle does not show stdout/stderr from the hidden rerun (it would leak the test set), so all you get back is the status and, if it finishes, the score. What has worked for me in notebook-only comps is to make the visible run behave like the rerun, and make the rerun unable to throw:

1. **Run on a full-size fake test.** The visible `test.csv` here has one row, so anything that only breaks at scale never runs. Build a pseudo-test from train rows (same columns and dtypes, `model` dropped, a fresh `id`) at roughly the hidden size, and point the pipeline at it when `os.getenv('KAGGLE_IS_COMPETITION_RERUN')` is unset. Things that pass on 1 row and die on N:
   - pairwise distance / linkage matrices for prompt grouping. Dense N×N float64 costs 8·N² bytes, so N = 10k is 0.8 GB *per matrix*, and the public lineages build two.
   - code paths that never trigger on one row: clusters of size ≥ 2, real groupbys, test-mean/std standardisation (std = 0 on one row, fine on many, or the reverse), Sinkhorn/balancing steps.
   - GPU batch memory once real long passages show up.
   An out-of-memory kill also comes back as a generic failure, so check peak RAM on the full-size run.
2. **Never let a stage raise.** Wrap each stage in `try/except`, fall back to a cheap member (the starter's TF-IDF + LR is enough), and always write `submission.parquet` at the end, after `assert len(sub) == len(test) and set(sub.id) == set(test.id)`. A broken stage then lowers the score instead of failing the submission. If the score comes back equal to your fallback's known LB score, something failed, and disabling half the stages per submission bisects it within a day at 5 submissions per day.
3. **Pin paths and offline assets.** Resolve the input dir by globbing both `/kaggle/input/competitions/name-that-llm` and `/kaggle/input/name-that-llm` (the starter already does this), and make sure every tokenizer/model loads from an attached dataset with `local_files_only=True`.

In RSNA Knee (also notebook-only; 3-study visible stub vs ~1.3k studies in the rerun) the full-size dry run caught a bug the stub never showed: a time-budget guard silently skipped parts of the model, so the configuration I had validated was not the one being scored. I would do step 1 before sharing a repro. It usually points at the line.
